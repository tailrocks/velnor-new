Notes:

- Velnor's test convention is `#[cfg(test)] #[path = "*_tests.rs"]
  mod tests;` in `src/`. Policy wants tests in `tests/` with canonical
  `tests.rs` suites (no `#[path]`, no children, no `src/tests/`).
- `GAP-TEST-003` false-positive class (probed): the helper does not
  follow production `#[path]` edges. `#[path = "lock.rs"] pub mod lock;`
  (mise `catalog.rs`), `#[path = "closure.rs"] pub(crate) mod closure;`
  (orchestrator `internal_plan.rs`, itself reachable from `lib.rs`) and
  the renamed forms (`#[path = "catalog_mbx.rs"] pub mod mbx;`) are all
  flagged. ≈29 production-referenced orphans plus most of the 169
  `mod`-name-unmatched files are this "frozen root + `#[path]` wiring"
  pattern, which is load-bearing (default resolution does NOT match, so
  Velnor cannot just drop the attributes). Triage per file in the
  normalization slice; file the helper gap upstream first.
- SIZE budgets count the whole package dir: orchestrator's 383 files =
  237 `src/` + 146 `tests/` exactly. Moving suites `src/`→`tests/`
  does not reduce SIZE — the 7 over-budget crates must split along
  module boundaries regardless.
- Runner debt is unmeasured (helper-blind until the merge). Probe it
  standalone (`check-gaps --root crates/velnor-runner` covers the
  registry-independent TEST/SIZE checks) before merging.

## Sequenced migration plan

Migration discipline (every step): map readers/writers/ownership
before each move; define forward plus rollback; sequence expand →
migrate → verify → contract; keep steps idempotent with partial
failure observable (per-rule-ID gap counts must monotonically
decrease — any increase fails the slice); verify old and new paths at
each transition (`cargo metadata` package count, `nextest list`
count, 37 loaded rules, gap diff); never contract destructively by
implication — stop after the requested stage passes and contract only
on explicit instruction.

Order is dependency-driven, not the objective's listing order: test
normalization precedes grouped moves because the currently vacuous
`tests-no-test-files-in-src` arms on move day and would fire on every
unmoved `*_tests.rs`.

- Add `rust-toolchain.toml` (`channel = "1.98.1"`): clears 3 rules.
  Readers: toolchain parity rules, mise, CI. Rollback: delete file.
- Probe runner TEST/SIZE debt standalone; append counts here.
- File upstream policy questions (helper production-`#[path]`
  reachability, `size-lib-main-150` fixture scope,
  `toolchain-channel-pinned` vacuous pass on missing file,
  `ci-build-runs-on` per-workflow scope): record issue links and the
  decided workaround-vs-wait for each before burning slice effort.

- Expand: add the 4 runner crates as root workspace members; extend
  `owned-packages.json` (9→13) and `package-groups.json` (runner
  roles); unify `deny.toml`/`clippy.toml`/nextest config at root.
- Migrate: single `Cargo.lock` (10 exact central deps + runner's set

### Step 3 — Test normalization (13 crates)

- Per crate, expand → migrate → verify → contract: add/extend
  `tests/` targets; move `#[test]` fns and `#[path]` suites out of
  `src/` (clears TEST-001/002); move-or-delete test-only support

  package gap count drops to the SIZE-only remainder; old (`src/`
  suite) and new (`tests/` suite) test counts reconciled before
  deleting the `src/` copies.
- Idempotent: scripted moves re-runnable; each crate independently
  committable. Clears ≈1100 findings; SIZE counts unchanged.

### Step 4 — Grouped moves (S4 `crates/<group>/<package>`)

- Proposed groups (decision point, names unchanged so
  `owned-packages.json`, `package-groups.json`, and CI job IDs are

  `crates/guard/velnor-archive-guard`.

  `MEMBERS`, `.velnor/config.toml`, docs links, `policy/` paths in

### Step 5 — Crate splits (SIZE)

- Split the 7 over-lines / 5 over-files crates along module
  boundaries until each fits 6000 code lines / 60 files (tests count
  — budget them inside the split design).
- Each new crate: group assignment + registry updates, dep-direction
  check (new edges must respect the direction table), `tests/`
  present from birth. Expand (new crate + re-export shims) → migrate
  (move modules, update dependents) → verify (workspace green, SIZE
  findings for that crate gone) → contract (remove shims, explicit).
- Clears GAP-SIZE-001 ×7, GAP-SIZE-002 ×5.

### Step 6 — Generator generic policy

- Generator-owned compliance this unblocks: `build` job on
  `ubuntu-latest` in all 6 workflows (emitted, not hand-edited —
  hand edits are overwritten on regen), `.cache/rust-policy`
  materialization + helper install before the `alint` CI job,

  `alint check`) and must not hand-edit generated workflows to fake
