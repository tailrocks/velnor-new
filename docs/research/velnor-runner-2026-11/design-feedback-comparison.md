# Comparison of the design feedback

Eight models reviewed the draft final design and the draft decision log (design-feedback brief v1, 2026-11-19), each alone. The owner asked this round to be more ambitious at the same confidence. This document merges the eight answers. Unlike the comparison of the proposals, it also carries the analyst's own read-only checks and assessments, and marks them as such. A **Check** says what was verified in code (velnor-new at `95de9b704b`, actions/runner, ARC, velnor-legacy) or in the evidence pack's raw run data (`ci-raw/runs_ci.tsv`, `jobs_compact.json`, 68 job logs); nothing was run on GitHub or the cluster. An **Assessment** judges an idea on speed, correctness, confidence and cost; by the owner's direction, a dependency being experimental or young is not a reason against it. Ids: `F-H` is a hole, `F-B` a bolder alternative; `I`, `N` and `S` ids are the decision log's; §, `C1`–`C7` and `M1`–`M9` are the draft's; a model's own finding is cited as, for example, "Claude Fable 5.2 (H6)". [M] is measured, [E] an estimate.

- **Ambition** is 5 to 8, median 6. The common complaint: every mechanism that removes a step (verdict without a job chain, verification on the tree that lands, verification before the push) is a stretch item after week 12, while the largest build (dispatcher, protocol client, hot Worker) tunes job start.
- **Soundness** is 5 to 7, median 6. The contract C1–C7 is praised ("the best work in the panel", Claude Fable 5.2). The holes are in C4, in the keys, in merge-queue semantics and in protocol details.
- The draft's own estimate is 6 min P50 in phase 3 (8 without merge-group selection). Claude Opus 5.5 and Muse Wonder Full land near it. Claude Fable 5.2 puts it lower (3–4 min), because a moved base is rarer than the draft assumes. Gemini 4 Carbon puts it higher (8–12 min), because of the holes below.

## Hardest problems: best attacks

- **One verification per landed tree while `main` moves.** Best attack: Claude Fable 5.2 (P1). The key is the hash of what the sandbox contains; selection is a lookup, so PR, merge group, push and nightly follow one rule; the PR verdict runs on the queue tip from trusted artifacts; output digests audit the key. Claude Opus 5.5 (P1) gives the order of yield: shrink the window (83–89% exact-tree hits), then per-root and per-package keys, then per-obligation receipts with in-flight join, then speculation for the remaining 10–15%. Gemini 4 Carbon adds the 2k − 1 prefix and bypass trees; GPT-6.2-Astra supplies the only replay of prefix prediction (36 of 45). GPT-6.2-Astra's caution stands: measure critical-path seconds saved, since "an 88% package overlap says little if the remaining 12% contains the 260 s test".
- **The single-test floor.** Best attack: GPT-6.2-Astra (1), the only one that measured what remains after the two loop splits (125–138 s; a 924.8 s test), with the remedy: build the expensive valid prefix once with the real code, clone the closed journal or the publication artifacts per case, keep the reopen, corruption and readback assertions in each case. Claude Fable 5.2 names the cost unit (`Journal::open`, 93 call sites) and a budget of 10 CPU-s per test measured alone. Gemini 4 Carbon and Gemini 4 Argon find the remaining loops, the serialised goldens and the fixture that is a cold example build. Muse Wonder Full adds the kill rule: a case still over 30 s is an end-to-end scenario and moves to the nightly run only with the owner's sign-off, because "this trades PR-time confidence for nightly confidence".
- **The 157k-line crate.** Best attack: Gemini 4 Argon (T3) and Gemini 4 Carbon (1): five or six crates along existing module boundaries, one test binary per package (356 links today in four crates), incremental state in node snapshots, and `velnor-runner-local` extracted so the two feature sweeps stop compiling the crate twice. Claude Opus 5.5 measured the unit: 61 s wall and 159 CPU-s for a one-file edit.
- **Zero cold start when GitHub is the cold start, and CI before the push.** Best attack: Claude Fable 5.2 (P2): they are one problem, the time from "this tree exists" to "a compiler runs on a warm disk", and one idempotent `ensure` with four callers (the agent's `velnor verify`, the push webhook, the witness job, the merge-group webhook) answers it: first cargo command at push + 3–4 s. GPT-6.2-Astra adds the join rule for edit snapshots (one producer per computation, cancelled only when its last consumer leaves). Claude Opus 5.5 and Claude Fable 5.2 measured the head start (42 s and 11 s median).
- **Placement and merge-first admission that GitHub does not expose.** Best attack: Gemini 4 Carbon (4): one scale set per priority and capability, total capacity in the header, and runner identities held by the dispatcher and decoupled from nodes, with idle identities dropped to zero under backlog so that queued jobs arrive as offers the dispatcher can sort. Muse Wonder Full supplies the kill rule: if a cache fetch at P90 costs no more than a delta rebuild at P50, per-job placement is dead weight. With F-B01, GitHub's choice of runner decides only where a witness prints logs.
- **Flake-free required checks.** Best attack: Claude Fable 5.2 (P4), by class: infrastructure causes are removed by sizing; old nondeterminism in untouched code is not executed under closure keys; changed tests run three times and any failure blocks; the rest gets one immediate, counted re-execution. Claude Opus 5.5 adds the burn-in of new tests (20 runs, 88% detection), Gemini 4 Carbon the 3× re-run with pressure counters, GPT-6.2-Astra and GPT-6.2-Sol the measurement rules (both directions, about 300 pairs).
- **A shared cluster at 92–95% CPU.** Best attack: Claude Fable 5.2 (P5): make latency independent of utilisation. Remove the demand (347 → about 25 runner-min per merged PR); put warmers, audits and speculation in `cpu.idle` cgroups, which yield in microseconds where pod preemption kills work; hold an SLO on CPU pressure under 2% for merge-path sandboxes. Claude Opus 5.5 and GPT-6.2-Sol add reservation over preemption. GPT-6.2-Astra corrects the picture: the fleet averaged 60%, 82% and 79% in the three samples, with the DE pair full and an FI worker at a quarter.
- **GitHub's own merge latency.** Best attack: Claude Opus 5.5 (T8) and Muse Wonder Full (T-1): a Velnor merge train that fast-forwards `main` by compare-and-swap. GPT-6.2-Sol gives the acceptance test: an atomic landing route with the same review and policy protection, or the experiment dies before it touches a protected ref.
- **Keeping concurrency defects observable without serial reruns.** Best attack: GPT-6.2-Astra (5): separate application deadlines from harness deadlines, run independent seeds on the real candidate in parallel, and keep a failing seed as a blocking regression.
