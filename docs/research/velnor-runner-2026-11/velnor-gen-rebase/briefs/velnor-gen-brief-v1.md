## Facts that changed the ground (verify, do not take on trust)

- CI on a PR is one big `rust` job (`shape = auto` with no timings file → one job; 31 "Check crate alone" steps), then `policy`, then `Required`. `Cache`, `rust-trim`, `ci-run-label` are side jobs. Four hand-written lint jobs live in `ci.yml`.
- `pr_ci = "label"`: a ready PR without a label runs only the quick set (plan, fmt, clippy, policy) and **`Required` turns green without tests**; drafts show `Required` green with a notice. `ci:run` runs tests once and is auto-removed; `ci:auto` runs on every push. `unlabeled` is not a trigger.
- The owner's requested flow (owner decisions 15–17): draft → nothing; ready → nothing; label attached → every push runs and cancels the previous run; label removed → stops; **a PR can never merge without a green verdict on its latest commit.**
- Measured after the cutover (small sample, 4 h): PR runs on the self-hosted scale set with queue P50 2–13 s; heavy PR runs P50 2.9 / P90 6.2 min; push runs P50 7.5 / P90 11.3 min; the long pole is the `rust` job (`rust-root` P50 67 s on PRs, 371 s on push). **Main is red; 157–167 of ~173 recent merges went in with a failing `Required` on the head commit (admin bypass inferred); the merge queue is configured but unused; `allow_auto_merge` is false.**
- The ruleset `protect-main` requires only `Required`, with no `integration_id` binding and an admin bypass actor.
- Reuse: none at the verdict level between PR, merge queue, main push and release. The only prior-run lookup (`velnor-ci merge-group-passed`, `skip_push_after_merge_group`) is off. Content addressing exists below the verdict (cargo fingerprints + restored mtimes, MBX CAS, PR build deltas #1107, helper digests).
- Selection (`velnor_rust::select`) narrows which tests **run**, not what **compiles**: clippy, the test build and doctests are `--workspace` (hard decision 11).
- Release of the tools rebuilds from source on GitHub-hosted runners; the release gate checks ancestry, not that `Required` passed (contrary to goals.md:77). There is no `runner-v` release workflow.
- Nothing in Rust executes Actions jobs today; the official C# runner runs every job. **`docs/goals.md:16` (and the macOS spec) still say the official runner executes every job**, which conflicts with the owner's Rust-only decision. Changing goals.md needs the owner's explicit approval.
- `StepKind::GeneratorCheck` exists but no planner emits it: no workflow runs `velnor-gen check`.
