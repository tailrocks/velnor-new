# Comparison of nine agent-native answers

Method. Nine models answered the owner's prompt ("reimagine the runner for AI agents: run agents' local verification through Velnor so the remote can skip what was already verified") from the agent-native brief v1 (2026-11-19; the brief was not in `briefs/`, so `~/.cache/ci-ambition/panel/agent-native-brief-v1.md` was used). Each answer is in `agent-native/*.md` and was read in full. This page only extracts and tabulates: the models' own figures, claims and recommendations, with no judgement. Tags [M] measured, [E] estimate, [T] target, [C] read from code are the models' own. "Fit" is what each answer says about owner decisions 1-24; "OQ" is an owner question. Costs are the models' agent-hour estimates. Short names used in tables: Fable = Claude Fable 5.2; Opus = Claude Opus 5.5; Sol = GPT-6.2-Sol; Astra = GPT-6.2-Astra; Argon = Gemini 4 Argon; Carbon = Gemini 4 Carbon; Neon = Gemini 4 Neon; W-Full = Muse Wonder Full; Wonder = Muse Wonder. Numbers from different answers are not normalised. Per-model idea ids (N01...) differ between answers; this page re-keys them as A01...

## The picture

| Model | Central idea (at most 30 words) |
|---|---|
| Claude Fable 5.2 | Verify once, inside the agent's loop, on gate hardware; CI becomes a lookup of an obligation on a tree. Mac results stay advisory; two cluster witnesses still count; `velnor ship` makes the label a lookup. |
| Claude Opus 5.5 | Agents' last local run happens inside Velnor as a cluster witness. The Mac finds reds, the cluster mints greens; `velnor verify` fills witnesses while the agent writes the PR text; the label is a lookup. |
| GPT-6.2-Sol | Move explicit pre-push `velnor verify` earlier: whole-tree keys, one Rust obligation, same ledger and node agent as the gate. Agent run becomes one of the two witnesses; count the 30 s saving once. |
| GPT-6.2-Astra | `velnor cargo test` from the agent's terminal runs on a warm Linux worker with a receipt. Two qualified observations made during development answer the label-time question as well as two made after it. |
| Gemini 4 Argon | Runner as the engine of the agent's inner loop: shim and daemon ship the worktree delta to a warm node; builder is Witness 1, the verifier subagent Witness 2; PR and group verdicts take 1-3 s. |
| Gemini 4 Carbon | Every `cargo` and `hk` command goes through a shim and daemon to warm x86_64 sandboxes minting T1 receipts; `velnor verify` adds T2 on the queue-tip merge; verdicts are 1-3 s lookups. |
| Gemini 4 Neon | One remote-by-default verification fabric: agent runs mint Tier-2 candidate receipts; Macs keep non-gating fast-red; PR and merge-group verdicts become 2-5 s ledger lookups with two cluster witnesses kept. |
| Muse Wonder Full | Run it once, wherever it first runs: shim in count-only mode first, sealed remote pre-push for one then two witnesses, and a PR verdict that reports reused, pre-push, run-now and fresh counts. |
| Muse Wonder | CI as shared memory of verified work: every agent command runs once in an observed sandbox and leaves a signed receipt; agents query the ledger first; the PR verdict is mostly lookup plus fresh C5 work. |
