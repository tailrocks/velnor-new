# Native consumer adoption corrections

Jackin's multi-package workspace exposed a native Required-job comparison
failure in SDK 0.1.61. Discovery sorted physical reader and writer job IDs;
native authority expanded logically sorted groups. Prefix-shaped group names
such as `rust-jackin` and `rust-jackin-agent-status` therefore produced different
dependency orders. Strict canonical job comparison correctly rejected the
disagreement with `native_authority_discovery_mismatch:required`.

The shared Required-job builder now sorts its copied physical dependency IDs
between the existing Plan and Jactionlint anchors. It does not deduplicate,
filter, or weaken canonical comparison. Additional policy validators retain
their existing positions after those dependencies.

The independently reviewed regression uses a real temporary two-package
workspace, public CLI plan and generation, exact Required dependencies, and
byte-identical repeated output. Only external Mise, Cargo metadata, and lint
process I/O use deterministic fixture responses. Discovery, metadata parsing,
native authority, rendering, and file writes execute the product code. The
first setup failure was discarded; the corrected fixture reproduced the exact
native-authority error before the builder fix and passed afterward. The full
CLI target passed 18 tests with no skips. A private development generator also
planned the actual Jackin checkout and generated two byte-identical trees;
these checks do not prove publication or authorize installing that generator.

Tap PR 515 identified two additional seed defects. The native adoption caller
now explicitly requests `opened`, `synchronize`, `reopened`, and
`ready_for_review`. The renderer and its strict caller-scope validator share
the same event representation. This preserves the default pull-request
activities and validates a draft when it becomes ready.

The generic transition contract admits only a single action-directory
component followed by `action.yml`, the exact generated cache-identity script,
and the existing root `scripts/` class. This does not authorize deleting every
matching path: the compiled protected transition remains the exact permission
inventory. Authoring still binds the protected base tree and every listed
path, mode, and Git blob. Candidate validation still requires the exact diff
and rejects extra, retained, or identity-changed deletions. Independent review
confirmed that a second runtime marker fetch would not restrict the authority
of these already reviewed immutable blobs, so no additional authoring seam or
network path was introduced.
