## Server cache access qualification

[GitHub's official GA notice](https://github.blog/changelog/2026-09-10-control-github-actions-cache-access-with-cache-mode/) and [workflow syntax](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#cache-mode) establish `read`, `write`, `write-only`, `none`, with scoped cache tokens enforcing access. GA is github.com/all plans; GHES support was not established. Job override/reusable-workflow cap semantics must be respected by any future typed emission.

[Official cache scopes](https://docs.github.com/en/actions/reference/workflows-and-actions/dependency-caching) isolate PR saves at `refs/pull/.../merge`; same-PR reruns can read these snapshots, other PRs/base branches cannot. Fork PRs can read allowed base/default snapshots. Thus private or secret data must never be archived merely because a key says trusted. Current Velnor policy intentionally does not add PR writes.

The current [latest actionlint release](https://github.com/rhysd/actionlint/releases/tag/v1.7.12), also the pinned installed validator, rejects both workflow/job `cache-mode` keys with exit 1. No released supported replacement was established. Renderer/IR lacks these fields. This is a proven validator limitation, not missing GitHub capability, and does not authorize bypassing validation. Pinned toolkit ignores environment mode but handles backend write denial as a warning; actual hosted scoped-token behavior still needs a negative experiment.
