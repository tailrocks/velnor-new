# CI obligation restoration

Status: working implementation and disposition ledger, 2026-10-03. No consumer
rollout, release publication, or hosted performance qualification is recorded
here. Private source, commands, identities, and deployment details remain in
external evidence; this document records only generic obligation families.

## Enabling architecture

Generation previously equated ownership of the `.github` directory with
ownership of every entry. Replacement deleted repository policy, automation
inputs, and workflow families even when the new adapter inventory could not
represent their substantive obligations. Required then judged only the reduced
generated inventory; an empty successful plan could report `no_work` while
unmodeled validation or publication remained necessary.

The structural repair has two boundaries: preserve repository-owned nonworkflow
entries during tree replacement, and represent each adopted validation family
as typed obligations included in Plan and Required. All workflow paths remain
generator owned. Portable workload declarations cannot be removed through the
stack ignore list; missing manifest dispositions fail generation. Preserving support files alone cannot restore a removed
workflow. Every prior obligation needs qualified replacement or an explicit
retirement decision before that consumer migration is complete.

Ownership semantics are normative in
[generated-file §3](../proposed/generated-file-contract.md). Primitive existence
proves neither execution equivalence nor release authority. Candidate generation,
negative fixtures, repository gates, reviewed regeneration, and resulting hosted
runs must establish those claims separately.

The Homebrew audit investigation reproduced a narrower correctness defect on
both Linux architectures: bare audit succeeds while an indexed malformed formula
is skipped during import. Explicit source-derived targets fail that negative
case. The adapter must retain the intended formula and cask coverage and avoid
introducing an unrelated style gate when strengthening admission. Exit zero
alone is not evidence that each indexed target was checked.

The generated package updater fixture body passed all sixteen lifecycle cases
against both the archived canary updater and a different repository profile.
Wrong-version, swapped-checksum and missing-support mutants each failed their
intended check. An independent verifier checked the compiled body, marker,
arguments, inputs, tool hashes, exact Ruby 4.0.7 and jq 1.8.2 executions, logs and
exit statuses in `/tmp/velnor-package-fixture-proof`. This proves that body and
those profiles. SDK source admission, product factory tests and hosted consumer
execution remain separate gates.

Helper reporting now has a common begin, source-owner execution and terminal
outcome frame. Static review accepted binding the compiled descriptor before
task and input hashes. The runtime must reconstruct the owner recipe from a
separate typed plan field; an embedded invocation recipe cannot authorize its
own root, profile or payload. That runtime branch remains closed pending the
typed authority migration. Shared source-SHA binding remains under review.
C09 helper evidence staging now uses exact owned channels and bounded one-MiB
admission, with regressions for partial failures, private environment data and
missing terminal reports. Independent source review and queued product tests
remain incomplete; no hosted or performance claim follows from this primitive.

The staged native helper composition now keeps the dependency boundary explicit:
Native owns compiled validation source and semantic descriptors; Mise owns the
neutral pinned tool and environment recipe; orchestration must compose and
check both. Its integration remains guarded. This removes the proposed Mise-to-Native import. Factory modules are registered and their staged source passed independent
review. Planner lowering, separate typed runtime owner authority and queued
product tests remain required before helpers replace guarded obligations.

reviewed exact-head regeneration, qualified validation and release trust
fixtures, and applicable hosted evidence. Performance measurements remain in
[performance qualification](ci-performance-qualification.md), with unavailable
measurements distinguished from passing CI.
