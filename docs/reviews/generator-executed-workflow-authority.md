# Executed workflow authority for generator compatibility

Observed 2026-10-03. Cross-host helper authority remains unavailable until
executed acquisition is proven. Official release membership alone cannot prove
which generator produced a downloaded plan.

## Primary protocol evidence

- [GitHub variables](https://docs.github.com/en/actions/reference/workflows-and-actions/variables)
  defines `GITHUB_WORKFLOW_SHA` as the workflow file's commit SHA and
  `GITHUB_WORKFLOW_REF` as its repository/path/ref identity. These are distinct
  from the tested checkout's head and event refs.
- [GitHub OIDC claims](https://docs.github.com/en/actions/reference/security/oidc)
  includes `workflow_sha`, `workflow_ref`, `run_id`, `run_attempt`, repository
  identity and event identity. Reusable jobs additionally have
  `job_workflow_sha` and `job_workflow_ref`; caller workflow identity does not
  substitute for callee identity. Token claims require signature, issuer,
  audience, lifetime and current-run validation before conferring authority.
- [Get a workflow run](https://docs.github.com/en/rest/actions/workflow-runs#get-a-workflow-run)
  documents `head_sha` and `path`, not a `workflow_sha` field. Treating
  `head_sha` as executed workflow source for every event is unsupported.
  [Workflow execution](https://docs.github.com/en/actions/concepts/workflows-and-actions/workflows)
  documents use of the workflow version at the event-associated commit/ref.
  An explicitly push-only source gate can use that event-specific rule;
  [pull requests](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows)
  use a synthetic merge commit distinct from the PR source branch head.
- [Get repository content](https://docs.github.com/en/rest/repos/contents#get-repository-content)
  supports an explicit commit `ref` and raw content responses. Future source
  acquisition must specify the authenticated immutable workflow commit and
  require a regular file; default-branch retrieval and followed symlinks do not
  establish exact executed source bytes.

Fetched primary documentation is saved in ignored `.firecrawl/` files:
`github-variables-workflow-authority.md`, `github-oidc-workflow-authority.md`,
`github-run-authority.md`, and `github-workflow-contents-authority.md`.
No remote mutation was performed.

## Existing project authority

`CurrentSourceContext` captures runner event, checkout and run authority.
`analysis_authority.rs` authenticates GitHub service responses and immutable
artifact bytes with pinned Gh. Neither constructs authenticated executed
workflow bytes or a generated-source receipt.

`ReleaseManifest` binds version, repository, source commit and per-target asset
digests. It has no generation compatibility version, generated workflow byte
receipt, or proof linking a run's planning binary to its acquisition steps.
An attacker-controlled plan cannot fill these missing facts. A manifest read
from the tested checkout cannot supply official release authority.

## Minimum structural proof

1. Authenticate current-run executed workflow repository, path and source SHA;
   retain caller/callee distinction where applicable.
2. Acquire complete source bytes at that immutable SHA through authenticated
   GitHub service responses. Compare complete bytes, not selected YAML fields.
3. Authenticate a source-owned generated-byte receipt or reproduce the exact
   generated bytes through a qualified generator path. Bind the receipt to
   generator source commit, compatibility schema, planning target/digest and
   acquired runtime target/digest. Authenticate both binaries independently.
4. Recheck current run and executable before consuming the private capability.

Arbitrary YAML interpretation is outside V1. Authenticated arbitrary workflow
bytes do not establish the planner's identity. A release-manifest extension
without a real protected publisher and actual generated-source binding would
also leave the enabling condition intact.

## Current disposition

The runtime release owner adds authenticated immutable official release
membership and retains `generator_executed_workflow_acquisition_missing` after
paired artifact validation. Cross-host runtime authority is denied. No private
workflow grant is constructed from runner strings, plan fields or local files.
The deferred structural dependency is the genuine generated-source receipt or
qualified exact regeneration path; it is not a runner implementation task.

Independent protocol review confirmed this disposition and the event-specific
push exception. This document adds no runtime implementation; release-pair
negative tests belong to the private runtime release owner.
