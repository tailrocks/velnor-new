## Reviewed boundaries and limits

Workload configuration uses `deny_unknown_fields`, closed package scripts and validated relative paths; no user-configurable raw command/YAML passthrough was found in these paths. Fixed adapter-owned shell is not itself a configuration escape hatch. The action obligation uses source-bound begin/terminal reports and retains failure outcomes. No new runner protocol implementation or independent task-result replay engine was found in reviewed workload/analysis/report paths.

Native identities currently deliberately retain unknown input provenance and disable task-result reuse. That is conservative correctness, but does not satisfy native affected-work or cache performance qualification. The generic descriptors, real CI/CD parity, supported tool installation and hosted measurements still need independent validation.

A proposed non-dot desktop execution-root finding was **withdrawn** after inspecting enclosing jobs: `delivery_desktop.rs:114` and cadence job defaults set `run.working-directory=config.root`; signing sets it explicitly. The root validation step intentionally starts at checkout root. No fix is required for that withdrawn allegation.

This review did not approve MBX internal formats or cache transport, release publication, live GitHub artifact provenance, full required-obligation parity, or any T01–T26 hosted result. Those require their assigned source/security/performance reviews and final generated-output evidence.

## Ownership review follow-up

**ARCH-06 / P1 — family-specific renderer APIs bypass the architectural boundary.** Independently confirmed by the `ownership_boundary` reviewer. `docs/proposed/architecture.md:53` permits only stack-neutral rendering and contract dependencies; its dependency table and workflow contract exclude Mise syntax and stack policy. Renderer currently owns:

- Mise syntax and installation semantics in `delivery_tools.rs::{setup_steps,exec_argv,exec_run,tool_specs,mise_prefix}`, desktop build/cadence/sign modules, and cache preparation envelope parsing.
- Cargo/crates.io interpretation in `release_reconcile_{common,registry,preflight,forge,entry}.py` and the `release_reconcile.rs` support bundle builder.
- Delivery topology/eligibility in `delivery_apt_workflow.rs`, `delivery_desktop.rs`, `delivery_desktop_cadence.rs`, `oci_jobs.rs`, and `oci_steps.rs`.
- Debian/GPG/feed, OCI image/index/digest, and Xcode/Swift signing policy in family-specific Python/source modules.

The enabling condition is `orchestrator/delivery_emit.rs::delivery_files` passing family configuration directly into renderer APIs that construct `Yaml`. `delivery_apt_tools.rs::prepare_helper` then reparses emitted `run` strings with `strip_prefix("python3 ")` and `split_ascii_whitespace`, separating the policy from validated command construction. Direct desktop `run()` helpers similarly bypass common workflow Step validation. Adding a renderer dependency on Mise would worsen the ownership violation rather than resolve it.

Structural extraction:

1. Mise owns fixed isolated command construction, tool installation/profiles and subprocess wrappers. Its strict canonical envelope decoder must be the sole owner. Explicit typed tool/cache descriptors replace renderer inference of Rust/Mise shell tokens.
2. Rust owns Cargo package/source/registry semantic payloads and proofs. Its fixed generated support policy modules may be supplied as source records; execution remains through Mise's fixed subprocess wrapper, not adapter-host process calls.
3. Orchestrator composes qualified authority, prerequisites, publication flow and generic workflow IR. Renderer serializes that validated IR; no family configs, stack-specific installation catalogs, policy scripts or run-text reinterpretation.
4. The existing exactly-eight-product-crates contract supplies no legal owner for APT, OCI or Swift/Xcode semantics. A reviewed architecture extension assigning explicit stack ownership is required before relocation. Silently moving those semantics wholesale into Mise or orchestrator does not satisfy the contract. The workflow contract's older seven-crate/Rust-only language also needs reconciliation with the authoritative architecture.

For the immediate Rust preparation envelope, the coordinator selected a neutral `SourceBoundHelper` descriptor with a compiled owner manifest and fixed auxiliary script lowering in Mise. Renderer checks the descriptor against the qualified compiled registry and emits only prepared generic command/environment data. Exact compiled-source verification precedes execution. Repository configuration cannot supply helper path/body/digest/argv; deserialized descriptors are not authority. The earlier internal PrepareTools suggestion was rejected because it would expand internal execution operations; do not implement it.

Regression requirements: adapter dependency graph remains directed through contract; renderer contains no new Mise selectors/Cargo/native policy parser; typed operation generates exact expected argv and source bytes; unknown operation/profile, injected script/path, altered generated helper and duplicated authority are rejected. Existing successful/failed publication and credential-boundary fixtures must survive extraction. These checks remain pending; no ownership approval is given.

The coordinator authorized an explicit named-stack ownership extension; its independently reviewed amendment and migration sequence are in `ci-performance-ownership-migration.md`. This resolves the previous specification ownership blocker, but source extraction and final-head gates remain incomplete.
