## Disjoint implementation ownership

1. Tool payload owner: Mise runtime/tool-home/source-subset definitions; renderer `cache_p08.rs`, `cache_steps_tools.rs`, `cache_elect.rs` and tool protocol tests. Coordinate the shared `cache_steps.rs` registration with MBX owner.
2. MBX owner: typed domain/snapshot model, renderer MBX construction, supported pinned action integration, `attach.rs` helper domain and `crate_jobs.rs` validation domain. Reserve these files against selector concurrent edits or use sequential patches.
3. Source owner: `source_cache.rs`, `source_prep.rs`, plan cache wiring and source-closure tests. Coordinate source subset migration with tool owner; no duplicate archiving.
4. Selection owner: coverage exports, crate job predicate/dynamic plan binding, final gate/baseline logic, base/candidate graph inventory and changed-input fixtures. MBX/selector both need crate job integration; integrate serially.
5. Scheduling owner: Rust obligation vectors/names, configuration cohort model, measured Nextest/fixture options; distinct outcome/report invariants.
6. Independent reviewers: protocol/security reads pinned bundled actions and generated output; selection reviewer compares actual plan/full coverage; performance verifier recomputes raw fresh-runner measurements. Implementer's summary is insufficient.

No implementation changed by this audit. No tests executed; source reading is evidence of defects and ownership, not behavior qualification.
