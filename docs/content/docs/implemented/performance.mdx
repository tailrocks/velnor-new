## 1. Cold run — 526.26 s green at `69dcc90` (fetch + compile + test)

Fresh clone at `69dcc90`, empty `CARGO_HOME`, empty `target/`,
direct rustup cargo 1.98.1 (MBX bypassed — the shared store cannot
be emptied non-destructively, so the outer build avoids it; in-test
cargo still resolves via shims), online fetch then offline test:

```sh
cargo fetch --locked                # 4.63 s, 65 Downloaded, 93.7 MiB home
cargo test --workspace --locked --offline   # 526.26 s wall, exit 0
```

Split: compile 97 s (`Finished` 1 m 37 s, 65 locked packages + 7
workspace crates, 0 downloads during test); test execution ~418 s
(cli 100.05 s, orch lib 29.44 s, orch int 282.03 s, mise 2.59 s,
rest &lt;1 s); ~11 s harness/link overhead. 1662/1662 pass. The cold
registry slows test execution itself (in-test cargo work
re-extracts: cli 100 s cold vs 18.82 s warm).
Proves: from-zero local compile+test is green in ~9 min here
(contention-inflated upper bound). Does not prove hosted cold
time (other CPU/arch) or empty-MBX-store compile.
Historical-partial (superseded): at `75f150a`, direct cargo with a warm 4.2 GiB
registry (NOT emptied — the old "empty-cache cold" label was wrong) took 56.06 s / 28.61 s compile.
CI datapoint: green run Plan `Build helper` 59 s (cold runner,
fetch + helper release compile, 53 downloads); crate jobs
compile cold-target/warm-sources (contract 14 s … orch 46 s).
UNMEASURED: controlled cold compile on the named CI runner; cold
registry download time on hosted runners.

## 2. Warm MBX rebuild (fresh checkout, warm store) — 4.90 s

Pinned (`mise exec` pins, MBX 1.21.0), fresh clone, empty target,
warm shared registry + warm MBX store, `--offline`:

```sh
cargo build --workspace --locked --offline
```

Run 1: 34.04 s wall (cargo 30.46 s), `mbx[cache]: 82 hits,
3 misses`, ~69 s compiler work avoided. Run 2 (second clone):
**4.90 s wall** (cargo 4.17 s), `85 hits, 0 misses`, `0 B`
transferred. The first touch paid 3 cold misses; the 0-miss
number is the warm-store headline. Historical: 3.30 s at
`75f150a` (MBX 1.19.0, 76 hits/1 miss).
Proves: MBX object reuse across checkouts — a fresh tree
materializes without compiling. Hits are not free (materialize +
link ≈ 4 s at 85 hits). Does not prove the CI MBX path: no
remote seed exists, so cache transfer/invalidation over the
network is unexercised and every hosted crate job reports `No mbx
cache found`.
UNMEASURED: CI cache-transfer time and MBX miss reasons on hosted
runners beyond `no_entry`.
