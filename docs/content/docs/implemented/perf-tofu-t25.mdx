## 4. Waste removed (with read counts)

One `velnor-actions-tofu::FileCache` per top-level phase, hoisted
(not per call): `discover` owns the prepare-phase instance across
detection, inventory, and diagnostics; `build_plan` owns the
plan-phase instance across every task; cover owns one across its
closure plus extension check. A construction-site scan pins exactly
these three (`cover_identity.rs`, `discover.rs`, `internal.rs`)
and zero constructions in tofu product code.

Per-root reads per `plan_internal` (single-file root), before →
after:

| Pass | Before | After |
| --- | --- | --- |
| Prepare: inventory (pinned) | 1 read/file | 1 read/file (shared on nested/table-less overlap) |
| Prepare: diagnostics (raw) | 2 walks, 2 lock reads, 2 config reads, 2 parses | 1 walk, 1 lock read, 1 config read, 1 parse |
| Plan: 3 task closures + identities | 7 walks, ~16 reads, 2 parses, 6 lock reads | 1 walk, ~4 reads, 1 parse, 1 lock read |

At width 10 that is roughly 90 fewer directory walks and 180 fewer
file reads per plan; every eliminated read is a cache hit serving
bytes identical to the live read (deletion tests prove hits serve
post-deletion bytes; failure kind/message rebuild verbatim;
oversize files over `MAX_FILE_BYTES` read through uncached so no
giant file pins memory).

Kept intentionally, each justified:

- Per-job plan-artifact downloads stay: every hosted job runs on
  its own runner and needs its own copy. Pinned minimal instead:
  at most one `Download plan` step per job, exactly one in every
  crate job and publish (`impl_tofu_t25`).
- `MAX_METADATA_LANES = 1` (Cargo-lock contention) and T18 lane
  staging stay: intentional serialization, untouched.
- `TofuLockSnapshot` capture/verify re-reads stay live: the
  second read is the drift proof; caching it would vacuous-proof
  the read-only contract.
- Pinned vs raw compartments never mix: orchestrator
  `read_repo_file` outcomes (handle-pinned, symlink-rejecting)
  and raw tofu bytes share one instance but separate maps, so the
  W6a-G2 pinned-handle guarantee never weakens.
- `files_for_prefix` still scans per unit: already once per unit;
  prefix bucketing without an index is still O(units x files),
  CPU-negligible, and pure.
- Cross-phase (prepare vs plan) instances stay separate:
  `prepare` keeps its stable signature (~200 call sites plus a
  source-text pin); each phase shares fully within itself.
